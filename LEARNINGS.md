## Process
| # | Lesson |
|---|---|
| L13 | Visual-QA tool (analyze_image) hallucinates at low resolution — verify via geometry probes (elementFromPoint + getBoundingClientRect) |

| L16 | User reads English only — restate bilingual tool output in English; minimize Chinese-labeled tool calls |
| L17 | **Async repo wrappers make every returned Promise truthy** — sync patterns like `if (repos.x.find())`, `!isLive()`, `.map/.filter` on the result, and in-place mutation of the "record" all silently break. | L18 | **Both stores must implement the full repo interface** — the JSON store is the reference; any repo group missing from pg-repos 500s at runtime on PG (JSON tests stay green and hide it). B5 added drafts/invites/documents/screening/auditLog. When adding a repo group: implement in BOTH stores + a PG roundtrip test |
| L19 | **In-place mutation + persist() doesn't work on PG** (persist is a no-op) — always add and call an explicit `save(entity)` on both stores after mutating |
| L20 | **Mimosa rejects SQL passed as variables or backtick templates** even fully literal — write every client.query with a single-quoted literal string; loops over tables need one literal query per table (or one aggregate literal). Same for test/bench scripts, not just server code |
| L21 | npm audit findings must be split runtime vs build-toolchain — astro/sharp/esbuild advisories never ship to production; gate strictly on runtime deps and register build ones with an exposure note |
| L22 | **A green dev database proves nothing about the provisioning path** — migrate.sql was DDL-only (seeds lived in a separate seed.sql) and was missing 2 tables created ad-hoc on dev. Rehearse from ZERO (drop/create/migrate/seed/counts) before any cutover; every schema change made directly on dev must be folded back into migrate.sql the same day |
| L23 | **Freeze manifests must exclude generated artifacts** (result JSONs, dump backups) that live beside the scripts — otherwise every verification rerun reads as drift and the seal loses meaning |
| L24 | **Ops scripts under security scanners: literal everything** — psql -c 'SQL' args, variable binary paths, and variable file args all get flagged as command injection; use pg-client literal SQL for DDL, literal relative paths with cwd for binaries, and per-run crypto.randomBytes for any credential-looking test value (even invalid ones like a wrong password) |
| L25 | **Ops scripts that WRITE artifacts into sealed directories must be added to the freeze before first daily run** — the hypercare log tripped the freeze gate on day one. The durable rule from rc5: exclude by class (all generated .json/dumps in scripts/), not by filename pattern additions |
| L26 | **Immutability triggers reshape write order:** once a BEFORE-UPDATE trigger guards delivered rows, any enrichment (e.g. ASP transmissionId) must happen BEFORE the status flip, in the same save — design the transmission failure path as "stay validated, staff retries" instead of a post-delivery queue |
| L27 | **Externally-issued tokens cannot use issue/consume** — the verifier never issued them; single-use needs burn-on-first-sight (hash the first-seen token, 409 forever after). Two distinct token disciplines in token.service: consume (ours) vs burn (theirs) |
| L28 | **Test suites that log in dozens of times need LOGIN_RATE_MAX override** — the per-account+IP limiter (10/5 min) is correct in prod but starves integration suites; env-tunable max, default unchanged. Also: profile routes must fetch the FULL user record — req.user is the stripped publicUser copy |
| L29 | **Every PG read must be shaped to the JSON-store contract before it leaves pg-repos** — raw rows are snake_case; three separate consumers broke on this (outbox rows missing to/text, mfa consume missing userId, save() dropping unlisted columns). Rule: no pg-repos method returns a raw row; each maps to the camelCase shape its service expects, and every WRITE persists every field the service may mutate |
| L30 | **A green JSON-store suite proves nothing about PG unless a PG-mode journey exists** — the deep iteration of 6 Oct found five production-path defects (B9 columns, field-dropping writes, phantom sent_at column, unshaped rows, missing B10 sequences) ALL invisible to 86 passing JSON tests. Every new service feature ships with a journey case in test/pg-mode-journey.test.js from now on |
| L31 | **A link-resolution parity gate beats eyeballing nav** — the /solutions hub was a linked 404 since the first SSG build and 4 more link bugs survived three audits; one scripted href→file sweep caught them all in seconds. Site-growing phases re-run it automatically now |
| L32 | **Asset gates must resolve references the way a BROWSER does** — href-only/leading-slash-only checks hid 161 broken product images since the first build (relative srcs on nested pages + an unshipped 8.5 MB library). The durable rule: any reference scanner resolves absolute-from-root AND relative-from-page-dir across href and src |
| L33 | **Automated gates certify the contract, not the pixels — drive the rendered pages** — 8 defects survived 141 green tests + a 48-check parity gate: boolean `stock:true` rendered as a "true" pill (81 cards + PDP), spec table destructuring scalars into "2 → T" rows, a CMS roundtrip test that overwrote the live AMC solution payload with a stub, 5 hero CTAs pointing at prototype-relative .html 404s, a wrong phone digit, 7 "pending import" legal stubs. | L53 | **Rotating a DB password under trust then flipping hba to scram has a wide, quiet blast radius (2026-10-17, rm 7.1, DAT-9)** — every tool that connected as the superuser relied on trust: the CI runner's `psql -U simal`, `GATE_ADMIN_URL` defaults hardcoding `simal:[REDACTED-ROTATED-2026-10]`, admin URLs derived from `DATABASE_URL` (run-gates/bringup/dr-drill/pg-mode-journey).
