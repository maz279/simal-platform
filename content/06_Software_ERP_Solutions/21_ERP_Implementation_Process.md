### Phase ? Discovery (Weeks 1–2)

**Goal:** Understand your business — deeply.

| Activity | Deliverable | Who's Involved |
|---|---|---|
| Kickoff workshop | Project charter, communication plan | Project sponsor, PM, key users |
| Process mapping sessions | As-is process maps (5–8 core processes) | Department heads, power users |
| Requirements gathering | Functional requirements document (FRD) | All department stakeholders |
| Data audit & migration scoping | Data inventory, migration strategy | IT team, database admin |
| Integration identification | Integration requirements list | IT team, third-party vendors |
| Infrastructure assessment | Hosting/server requirements | IT team |

**Client Time Commitment:** ~8 hours total across key stakeholders

### Phase ? Solution Design & Planning (Week 3)

**Goal:** Map your requirements to UniERP capabilities. Identify gaps (and how we'll close them).

| Activity | Deliverable | Who's Involved |
|---|---|---|
| Solution blueprint | Detailed solution design document — module configuration, workflows, reports | Solution architect, PM |
| Gap analysis | Gap-fit matrix — fit, fit with config, gap (custom dev) | Solution architect |
| Project plan finalization | Detailed project plan with milestones, dependencies, resource allocation | Project manager |
| Infrastructure setup | Dev, test, and production environments provisioned | System admin |

**Client Time Commitment:** ~6 hours across department heads

### Phase ? Configuration & Development (Weeks 4–6)

**Goal:** Build your UniERP. Configure, customize, develop.

| Activity | Deliverable | Who's Involved |
|---|---|---|
| Module configuration | Configured modules per solution blueprint (CoA, workflows, user roles, reports) | Functional consultants |
| Data migration | Master data (customers, vendors, products, chart of accounts, employees) and open transactions migrated | Data migration specialist |
| Integration development | API/web service connectors built and unit-tested | Developers |
| Custom development (if any) | Gap-filling custom modules/features developed | Developers |
| Sprint demos (weekly) | Working software demo every Friday — you see progress | Functional consultants |

**Client Time Commitment:** ~4 hours/week (weekly demo review, data validation)

### Phase ? Testing (Weeks 7–8)

**Goal:** Ensure everything works — correctly, completely, and fast.

| Activity | Deliverable | Who's Involved |
|---|---|---|
| System integration testing (SIT) | SIT test cases executed, defects logged and resolved | QA team |
| User acceptance testing (UAT) | UAT test scripts, UAT sign-off by process owners | Key users (client) |
| Performance testing | Load test results, response time benchmarks | QA team |
| Data validation | Reconcile migrated data with source systems | Finance & ops teams (client) |
| Security testing | Access control validation, penetration test report | Security team |

**Client Time Commitment:** ~20 hours across key users (UAT execution)

### Phase ? Training (Weeks 9–10)

**Goal:** Your team is confident and ready to use UniERP on Day 1.

| Activity | Deliverable | Who's Involved |
|---|---|---|
| Train-the-trainer | Department champions trained as internal trainers | Power users (client) |
| End-user training | Role-based training sessions (Finance, HR, Sales, Inventory, etc.) | All end users (client) |
| Training materials | User manuals, quick reference guides, video tutorials | Training specialist |
| Practice environment | Sandbox environment for hands-on practice with real data | All end users (client) |
| Competency assessment | User readiness assessment; additional support for users who need it | Training specialist |

**Client Time Commitment:** ~12 hours per end user (3–4 sessions × 3–4 hours), ~20 hours for power users

### Phase ? Go-Live (Week 11)

**Goal:** Cut over to UniERP — smooth, controlled, supported.

| Activity | Deliverable |
|---|---|
| Final data sync | Last incremental data migration from legacy system |
| System freeze on legacy | Legacy system set to read-only |
| Go-live activation | UniERP turned on for all users |
| Hypercare support (Week 11–12) | On-site + remote support team — immediate response to any issue |
| Daily stand-up (Week 11–12) | 15-minute daily check-in — issues, priorities, resolutions |
| First week-end close | Support team assists first financial close in UniERP |

**Go-Live Strategy:** We typically recommend a **big-bang go-live** for companies with < 500 users and a **phased go-live** (module by module, or location by location) for larger or more complex deployments. We'll recommend the right strategy during Phase ?.

### Phase ? Ongoing Support (Week 12+)

**Goal:** Continuous improvement. You're never alone.

| Tier | Response Time | Scope |
|---|---|---|
| **Critical (P1)** — System down | 1 hour | 24/7 |
| **High (P2)** — Major functionality broken | 4 business hours | Business hours + on-call |
| **Medium (P3)** — Minor issue, workaround exists | 8 business hours | Business hours |
| **Low (P4)** — Cosmetic, enhancement request | 2 business days | Business hours |

**Support Includes:** Bug fixes, configuration adjustments, minor enhancements, new user setup, performance monitoring, quarterly health checks.

## Frequently Asked Questions

**Q: Can we use our existing server/hardware, or do we need new infrastructure?**
UniERP runs on standard Linux servers (on-premise or cloud). If you have suitable infrastructure (8+ GB RAM, 4+ cores, SSD storage), we can deploy on it. Most clients choose cloud hosting (AWS, Azure, or our managed hosting) for reliability and scalability. We'll assess during Phase ?.

**Q: What if we need to go live earlier than the standard timeline?**
Accelerated timelines are possible but require higher client team availability and reduced scope. We can discuss a fast-track plan during Phase ?. We won't compromise on testing or training quality.

**Q: How do you handle data migration from our legacy system?**
We provide data templates (Excel) for each master data type. Your team extracts data from the legacy system into these templates. Our team validates, transforms, and loads into UniERP. We typically run 2–3 migration test cycles before the final go-live migration. For complex migrations, we can build ETL scripts.

**Q: What happens if we discover major issues during UAT?**
That's exactly what UAT is for — finding issues before go-live. All UAT defects are classified (Critical/High/Medium/Low) and resolved before go-live. If critical issues remain unresolved, we recommend delaying go-live (at no additional cost for the delay caused by our deliverables).

**Q: Do you provide post-go-live support, or are we on our own?**
Post-go-live support is included. The first 2 weeks after go-live are "hypercare" — our team is available on-site or via video call with immediate response. After hypercare, you transition to our standard support SLA. We also offer annual maintenance contracts (AMC) for ongoing support and upgrades.
