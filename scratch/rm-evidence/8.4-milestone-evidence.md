# Milestone 8.4 — GA4 behind consent (SEO-5 residue) — Evidence

Date: 2026-10-17 (session rm-8.4). Rig: Chrome headless (CDP + Network/Log
capture) against gate builds; portal DB scratch-only for builds (DAT-7).

## 8.4-1 — Environment + consent-gated loader

- `PUBLIC_GA4_ID` read in BaseLayout frontmatter; `<meta name="ga4-id">`
  emitted **only** when set. `apps/site/.env.example` documents the shape;
  `apps/site/.env` (gitignored) is the local slot; CI `build` job passes
  `PUBLIC_GA4_ID: ${{ vars.PUBLIC_GA4_ID }}`. No real ID is committed —
  unset means GA4 fully off (verified: no-ID build has no meta).
- `public/assets/js/consent-defaults.js` now sets
  `window.__simalConsentGrants` synchronously (denied defaults, then the
  stored `simal_consent` cookie's grants) alongside the Consent Mode
  default/update — closing the returning-visitor gap.
- Loader deviation from the roadmap snippet, with reason: the roadmap
  asked for a processed (bundled) `<script>`, but Astro **inlines** small
  processed scripts under `assetsInlineLimit` (proven in the first build:
  the loader landed as an inline module at the end of `<body>`), which
  `script-src 'self'` would block — the exact failure the v1.2 correction
  warns about. The loader therefore ships as
  `public/assets/js/ga4-loader.js`, the same external-file pattern rm(3.3-1)
  chose for the consent defaults. Deferred classic scripts execute in
  document order (defaults first, loader second), and the gate asserts
  that order plus zero inline executable scripts in the built HTML.
- CSP: GA4 hosts added to **all three** site policies (BaseLayout meta,
  `scripts/dev-edge.mjs`, nginx site vhost in
  `infra/nginx/portal-staging.conf`): `script-src https://*.googletagmanager.com`;
  `connect-src` + `*.google-analytics.com`, `*.analytics.google.com`,
  `*.googletagmanager.com`; `img-src` explicit GA4 hosts. New dev-edge code
  verified on a scratch port (:8102). Addendum (same day, user request):
  the long-running :8100 dev-edge was restarted with its original launch
  config (`SITE_DIST=apps/site/deploy-docroot`, pid 22592 replacing 8824);
  `GET :8100/` now serves the new header (`script-src … *.googletagmanager.com`,
  `connect-src … *.analytics.google.com`) with home 200, the 8.3 sitemap
  distribution intact, and `/api/health` proxying ok.

## 8.4-2 — Banner events + withdrawal

- `setConsent()` (single funnel for Accept-all, Reject, and Save) now
  mirrors grants to `window.__simalConsentGrants` and dispatches
  `simal:consent-accepted` with the grants object on every call.
- Withdrawal (previously granted + GA4 live in-page): sets
  `window['ga-disable-<id>'] = true`, then `location.reload()` — after the
  reload, consent-defaults computes denied from the cookie and GA4 never
  loads. Gate-verified end to end.
