**Finding found and fixed by this pass (real defect, not a test artifact):**
`PEN-INTERNAL-01` — the inbound bounce webhook verified `HMAC(secret, JSON.stringify(parsedBody))`
and ignored timestamps, so a captured request could be **replayed indefinitely** (the suite
proved a 10-minute-old timestamp was accepted, then a fresh one). Fixed to the roadmap 2.3-1
design: raw-body signature bound to a millisecond timestamp, ±5-minute window, strict JSON parse
after verification (`apps/portal/src/services/routes.js`). The api suite's bounce case now also
asserts: body-only signature → 403, stale timestamp → 403, fresh bound signature → 200.

**Baseline alignments implemented while tracing (10.3-2 spill-over, all covered by tests):**
- **GOV a20**: failure-based lockout — 5 consecutive failed logins per account+IP within 10 min →
  15-minute lockout (429), success resets; proven in-suite (A4) and in the browser
  (`10.3-browser-sweep/login-lockout-15min.png` — "account locked for 15 minute(s)").
- **GOV a21**: tiered limits — public forms 5/10 min, public reads 120/min, status 20/min,
  staff/CMS 300/min (strict mode proven H1/H2; `NODE_KYC_TEST` relaxation documented and
  `RATE_LIMITS_STRICT=1` overrides it).
- **GOV a23/a24**: Lighthouse assertions extended to CLS ≤0.05 and TTFB ≤200 ms.

**UI finding fixed in the browser pass:** `PEN-INTERNAL-02` — the viewer role's console
advertised and routed into pages its role cannot open (Users/Settings for non-admins; the
dashboard for viewers, whose `analytics` call 403s), producing dead ends and 403 toasts. The
sidebar is now capability-gated and a viewer sees an honest read-only notice. The deeper issue —
the `viewer` role's declared `read`/`export` permissions are bound to no route — is recorded as
**RTM DEV-13** for a product decision; API policy (deny-by-default) was **not** loosened.
Evidence: `10.3-browser-sweep/viewer-readonly-landing.png`.

firm cannot be contracted from this environment, so the engagement was executed by **three
independent, isolated test agents** (auth / KYC / CMS) given only the commission pack, the
requirements baseline and the running application — no source, no repo tests, no engineering
suite; no code changes.
