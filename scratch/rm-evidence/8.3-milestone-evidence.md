## 8.3-1 — Real modification times (Fix A, B14)

- `scripts/migrate.sql` block **B14**: `updated_at BIGINT` (nullable, epoch-ms,
  same convention as `content_blocks.updated_at`) added to `products`, `brands`,
  `legal_policies`, `product_deep`; backfill = newest `cms_revisions` row per
  record (`WHERE updated_at IS NULL`, idempotent — verified by double-apply).
- Live-DB verification before B14: only `content_blocks.updated_at` existed
  (V-173 confirmed). Backfill on the dev DB stamped 3 products; remaining
  `cms_revisions` rows reference long-deleted e2e fixtures, and `brands` /
  `legal_policies` / `product_deep` have no revision rows yet, so those rows
  stay NULL and fall back until their next edit. This is data reality, not a
  logic gap: the backfill query matches the roadmap's Fix A.
- Every write path in `apps/portal/src/services/cms.service.js` now stamps
  `updated_at = Date.now()`: `createProduct`, `updateProduct`, products
  rollback, `upsertProductDeep` (insert+update), `upsertBrand` (insert+update),
  `upsertPolicy` (insert+update), legal rollback, and `renameCategory`
  (renders on PDPs, so a rename is a real product modification).
  `updated_at` is exposed in product/brand/product_deep/policy reads.
- Build roles need no change: `prod-db-roles.sql` grants are table-level
  (`GRANT SELECT ON ALL TABLES` for `simal_build`, DML for `simal_app`), so
  new columns are covered.

## 8.3-2 — Threaded lastmod + regression case

- `apps/site/src/pages/sitemap.xml.js`: all entity queries now select
  `updated_at` (`content_blocks` via `MAX(updated_at)` per `entity_id`;
  products via `GREATEST(products.updated_at, product_deep.updated_at)` so a
  deep-spec edit moves the product URL), the roadmap `ts()` helper converts
  epoch-ms → `YYYY-MM-DD` with `VERIFIED_BASE_DATE` fallback for
  NULL/never-edited rows, and every loop passes `ts(r.updated_at)`.
  Static routes keep the constant.
- Durable regression gate `scripts/ci/sitemap-lastmod.mjs` (wired into
  `scripts/ci/run-gates.mjs` as `sitemap` and into `.github/workflows/ci.yml`
  as job `gate-sitemap-lastmod`): scratch DB only (DAT-7), boots the portal,
  edits one entity of every sitemap type through the real CMS API, rolls a
  product back, builds the site, and asserts 16 checks — schema, stamps,
  rollback re-stamp, multiple distinct dates, edited = today (UTC),
  untouched = fallback, static = constant, valid dates, ≥200 urls.
