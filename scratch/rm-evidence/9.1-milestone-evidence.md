## 3. Defects fixed so that every gate runs on a real runner

1. **secrets-scan**: gitleaks found 11 findings in history; the mirror used a grep stand-in.
   - The job now runs the pinned gitleaks 8.28.0 CLI, checksum-verified, over full history. It needs no gitleaks-action licence and no GitHub API.
   - `.gitleaks.toml` allowlists the `FREEZE_MANIFEST.json` hashes **at rule level only**. In 8.28 a global `paths` allowlist exempted the whole file from every rule, even with `condition = "AND"`; a Stripe key and a GitHub PAT planted there went undetected in a test.
   - `.gitleaksignore` holds the triaged historic fingerprints. Its old `tools/` line was not a fingerprint and excluded nothing.
2. **Live credentials committed** (see "Security finding" below). They are scrubbed from HEAD, and two tracked scratch scripts are untracked.
3. **security**: `security-audit.js` was meant to boot the JSON store but never blanked `DATABASE_URL`. It ran against the rig database locally and hit ECONNREFUSED on the platform.
4. **gate-authz**: missing `npm install pg`.
5. **gate-facts-consistency**: the e2e preferred `DATABASE_URL`, which on the platform is the empty service database. It now uses `E2E_DATABASE_URL` or a scratch database.
6. **integration**: `pg-mode-journey` shelled out to `tools/pgsql/bin/psql.exe`. It now migrates and seeds through the `pg` client.
7. **unit**: the job installed nothing, but the suites boot `server.js`, which imports `pg`. It now runs `npm ci`.
8. **unit**: the suites depended on git-ignored `apps/portal/data/` files, `watchlist.csv` and `products.json`. They now use tracked fixtures; `server.js` gains a `PRODUCTS_JSON` override. Reproduced first in a fresh clone (7 RFQ failures).
9. **gate-link-crawl / gate-a11y**: `lib.mjs` required `pg` at import. It now loads `pg` lazily, with call sites unchanged.
10. **gate-a11y**: the job had `needs: [build]` but never downloaded `site-dist`.
11. **Chrome jobs (a11y, ga4-consent, lighthouse)**: `apt-get install chromium-browser || true` is a snap stub on Ubuntu 24.04 and the `|| true` masked its failure. They now use `browser-actions/setup-chrome`, and `--no-sandbox` where Chrome runs as root. `psql` is installed when it is absent.
12. **lighthouse**: `upload-artifact` ≥ v4.4 skips hidden paths, so `.lighthouseci` (the NFR-1 reports) was dropped with only a warning. The upload now sets `include-hidden-files: true` and `if-no-files-found: error`.

The local mirror (`run-local-ci.mjs`) now runs the real gitleaks and passes
`E2E_DATABASE_URL`.

## 5. Security finding: committed live credentials (owner action pending)

- **What was exposed:** the rig's live `ADMIN_PASSWORD`, `REVIEWER_PASSWORD` and `VIEWER_PASSWORD` appeared verbatim in tracked files, in commits `cbdcde5` and `ce8d072` (pushed to `origin`).
- **The sweep:** I compared every tracked file and all history against the live `.env` values, matching exact values by hash. Gitleaks flagged only the reviewer and viewer passwords; the admin password was found only by the exact-value sweep.
- **What is fixed:** HEAD is clean. The scripts read from the environment or the git-ignored `.env`.
- **What is outstanding:** history is append-only, because `main` rejects force-push. The values are dead only once they are **rotated**. Rotation was not performed in this session, because writing the secret store needs owner approval.
- **What the owner needs to do:** set new values for those three keys in `apps/portal/.env`, then restart the portal. The portal re-applies env passwords at boot (`auth.service.js` bootstrap).
- **Tracking:** `.gitleaksignore` marks these fingerprints `ROTATION PENDING`. Admin login also requires TOTP when MFA is enforced; reviewer and viewer have no MFA.
