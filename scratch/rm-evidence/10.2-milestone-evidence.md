## Task 10.2-2 — DR drill fixed, then executed with measured results
`scripts/dr-drill.mjs` rewritten. The five roadmap defects fixed:
1. URLs from the environment first (`DATABASE_URL` / `ADMIN_DATABASE_URL`), `.env` only as a
   guarded fallback — the recovery DB is created/restored by the ADMIN role, not the app role.
2. **RPO measured**, not hardcoded: snapshot end → simulated-disaster instant on the database
   clock.
3. **RTO measured** and PASS computed against the targets (RPO ≤ 1 h, RTO ≤ 4 h) — no
   templated "(PASS)".
4. Backups written outside the repo (`DR_BACKUP_DIR`, default OS temp) — PII never lands in
   the tree.
5. `docs/DR_DRILL_EVIDENCE.md` is **appended** to, never overwritten; the recovery DB is dropped
   in a `finally`.
Additional hardening from actually running it:
- the snapshot is taken inside **one REPEATABLE READ transaction**, so counts, data and
  checksums describe a single point in time;
- integrity is row counts **and** a canonical (`to_jsonb`) md5 content checksum per table;
- temporal columns are read as raw text — a `date` parsed into a JS Date and sent back through
  `toISOString()` **shifted the day** in the non-UTC rig session (Asia/Kuala_Lumpur). The first
  run FAILED on `invoices` for exactly this; the old count-only drill could never see it;
- the first checksum version used `row_to_json`, whose **physical column order** differs between
  a long-lived ALTERed schema and a fresh migrate — a false mismatch on `announcements`; fixed by
  `to_jsonb`.
Final run: **PASS** — integrity identical across 27 tables / 4,266 rows, **RTO 2.23 s**,
**RPO 0.165 s**. Both FAIL runs remain in the evidence file as proof the drill now detects real
defects.
**Deploy proof (5.2) from a CMS publish:** `10.2-2-deploy-proof.log` — announcement edit →
publish → SSG processed 15.3 s → marker served at the deploy origin → restored, marker gone.
