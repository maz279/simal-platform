## Task 9.3-1 — Outbound error sink
- `apps/portal/src/server.js`: inside the existing `status >= 500` block, every 5xx is
  POSTed (fire-and-forget, `.catch(() => {})` — a sink outage can never 500 the
  handler again) to `OBSERVABILITY_WEBHOOK_URL` as
  `{text, requestId, path, status, message, ts}` — Slack/Teams-compatible `text`;
  NOT Sentry-compatible (per roadmap note).
- `apps/portal/src/lib/log.js`: `redactObsMessage()` — PDPL redaction + 200-char cap.
  **Roadmap-snippet defect caught by the unit test**: `\b\d{6,}\b` never matches an
  IBAN digit run glued to its `AE` prefix (E and 8 are both word chars — no boundary);
  the shipped regex is `(?<!\d)\d{6,}(?!\d)`, which redacts maximal digit runs.
- `apps/portal/.env.example`: `OBSERVABILITY_WEBHOOK_URL=` documented as distinct
  from the ERP `WEBHOOK_URL`.
- Rig stand-in sink: `scripts/observability-sink.mjs` (listening on :8095, appends
  to `scratch/observability.jsonl`) — running on the rig; portal `.env` points at it
  and the portal was restarted to load it.

## Task 9.3-2 — Uptime probe with alerting
- `scripts/uptime-probe.mjs`: fetches `PUBLIC_ORIGIN` (default :8100 edge, which
  proxies /api to the portal and 502s when it is down) with a 5 s timeout; exits
  0/1; on failure POSTs `[simal] UPTIME FAIL …` to the webhook. Alert-hook fallback
  reads `apps/portal/.env` (guarded) — a bare scheduled task has no env of its own.
  `hypercare-daily.js` stays untouched (it boots its own portal — v1.2 blocker note).
- Scheduled on the rig: `schtasks /Create /TN SimalUptime /SC MINUTE /MO 5 /TR
  "cmd.exe /c cd /d <Codebase> && tools\node\node.exe scripts\uptime-probe.mjs >>
  scratch\uptime.log 2>&1"` — created, first manual run `UP … HTTP 200`
  (`scratch/uptime.log`).
